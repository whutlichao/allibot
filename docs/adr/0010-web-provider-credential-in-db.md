# 0010 联网 provider 凭据入库：对「库内不存密钥」的显式例外

## Status

proposed（2026-11-04）

## Context

M1 的 D1.10 与 M2 的 D1.4 立了两条纪律：模型密钥只从进程环境读、不写 SQLite；HTTP、进程输出与事件只回掩码或「缺凭证」状态。M2 把这个纪律一路写到了部署说明与备份章节，`remote_consent_scope` 也只为「告知」留位，不为凭据留位。

而 T12 的词条（`GLOSSARY.md` 的「联网 provider 凭据」）要求的是另一种东西：五家带凭据 provider（brave / tavily / perplexity / jina / exa）各一把 key，**明文存 `web_provider_credential`**，至多一行默认，解析顺序是「环境变量指定 provider → 凭据表默认项 → 已配置项固定顺序 → 免凭据回退 `exa` MCP」，且**凭证值库内优先、环境变量兜底**。

两者正面冲突，且不是可以含糊过去的冲突：要么库里有明文密钥，要么词条的「库内优先」做不到。这个决定难以撤销（一旦有用户的 key 在库里，回退意味着让他们重新配置，且已备份的数据目录里已经留下了密钥），未来读者一定会问「为什么这里可以把 key 存库」，所以按 ADR 的门槛它必须显式裁定，而不是在实现票里顺手破例。

## Decision

1. **模型密钥与联网凭据分开裁定。** 模型密钥仍然只从进程环境读、不写库（M1 D1.10 不变）。联网 provider 凭据是**唯一**允许明文入库的密钥类别，落点是专表 `web_provider_credential(provider, api_key, is_default, created_at, updated_at)`。纪律的正确表述改为：「模型密钥不进库；联网 provider 凭据是唯一例外，且有专门的正本表与专门的边界。」不新增第二类例外，也不把这个例外扩展成通用 secret store。
2. **明文是选择，不是疏忽。** 不做加解密：本仓没有 KMS 或第二套密钥来源，引入「用一把本地密钥加密另一把本地密钥」只会制造安全剧场。真正的边界是「库文件本身与它的备份」，这个边界在部署说明里写明，让 owner 知道备份里带着什么。
3. **凭据不进入任何人类可见的读数以外的地方。** HTTP 读数只回掩码（`sk-…abcd`）；密钥值不进 SSE 帧、不进日志、不进轮次 reason、不进审批载荷。失败信息里若出现 provider 回显的片段，按既有 `maskSecret` 在落库前掩码。
4. **库内值优先、环境变量兜底。** 同一 provider 两边都有时用库内值——这是「在 UI 里换 key 立即生效」的前提；`allibot_WEB_<PROVIDER>_API_KEY` 只是没有库内值时的兜底，不是正本。
5. **至多一个默认。** `is_default = 1` 由部分唯一索引保证；provider 取值由 CHECK 限定为五家。这样「默认凭据」是数据事实而不是「按时间取最新」的隐式规则。
6. **备份边界必须写进部署说明。** 数据目录备份从此包含明文密钥，这与 M2 已写明的「数据目录承载 allibot.db / attachments / 迁移清单」并列，是新增的一条已知事实，不能只存在于代码里。

## Consequences

- 用 UI 切 provider、轮换 key 不需要重启进程，这是词条要的可用性；代价是密钥落盘，且落盘位置就是 owner 每天都在备份的那个目录。
- 备份、磁盘快照、`<data-dir>.backup-*` 目录都从此可能与密钥同体。部署说明必须显式写这一条，否则 owner 无法做出「要不要整目录备份」的判断。
- 一旦有用户的 key 在库里，「把凭据搬回环境变量」就是一次需要迁移的决定：本 ADR 之后想撤销它，要新开 ADR 并处理已有数据，而不是改一行代码。
- 五家 provider 的 key 是同一种形状（一行明文 + 一个默认标记），所以新增第六家不需要新 ADR；改成加密存储则需要。
- 与 ADR-0007 无关：本 ADR 只裁「密钥能不能入库」，工具判定顺序、审批批次、read-only 硬顶全部沿用 0007。

## Old ADR Correspondence

- 与 ADR-0004（SQLite 单文件正本 + 迁移闸门）一致：`web_provider_credential` 是普通 schema 步骤 v24，仍走严格 +1、单事务、备份与审计台账。
- 与 M1 D1.10 / M2 D1.4 的关系是**收窄而非推翻**：那两条说的是模型密钥，本 ADR 不改变它们；只是把「密钥」这个大类拆成两类并给联网凭据单独裁定。
- 与旧仓「联网 provider 凭据」词条一致：词条要求明文入库、库内优先，本 ADR 采用词条，并把边界与代价写清。
