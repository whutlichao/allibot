# 0005 以 SQLite 记忆表替代 ReMe 文件工作区

## Status

accepted（2026-11-03）

## Context

GLOSSARY.md 的「长期记忆 (Long-term Memory)」把记忆落在 Agent 家目录下的 ReMe 工作区（`~/.allibot/agents/<member_id>/reme/`）：一个成员一个工作区，跨 session / target / 项目共享召回，轮次收尾自动写回、回复前按关键词检索注入，没有开关，不启用 embedding。用户已定夺 D5：以 SQLite 记忆表替代 ReMe 文件工作区；成员级、跨 target 召回、关键词检索注入、轮次收尾自动写回、无开关；不引入 embedding、不新增凭据面。原词条的「Agent 家目录 reme/」必须在本 ADR 中记录为被本决策替代。这个决定影响记忆落点、备份单位、召回质量与运维面，回退成本高，且未来读者会问「为什么记忆不在文件里」。

## Decision

1. **落点**：SQLite 表 `agent_memory`，随业务库 `allibot.db` 一起落在数据目录，随整目录备份与迁移。字段至少包含：`id`、`member_id`、`content`、`keywords`、`source_target_id`、`source_message_id`、`created_at`。一个成员一个逻辑集合；不按 target / 项目 / session 切分，因此跨 target 召回是构造事实。
2. **写回**：轮次收尾由编排自动写入一条记忆卡片；卡片内容是该轮的可读摘要（触发消息摘录 + 本成员回复摘录 + 任务上下文，若有），关键词由确定性 tokenizer 从同一段文本提取。写回不依赖模型自述，也不额外调用模型；没有「记忆档」或「长期记忆开关」。
3. **召回**：回复前用本轮输入（触发消息、任务标题、最近上下文）的关键词检索该成员的记忆行，按关键词重合度与时间新近度排序，取固定上限（默认 8 条）注入 system prompt 的记忆段。召回只影响本轮理解，不改消息、未读、唤醒或回应纪律。
4. **不引入 embedding**：不做向量检索、不新增 embedding provider、不新增凭据面；检索是关键词匹配，允许召回质量低于语义检索，这是本决策接受的代价。
5. **替代关系**：`~/.allibot/agents/<member_id>/reme/` 不再是落点；不创建 `reme/`，不读取旧 `MEMORY.md` / `<topic>.md`，不自动导入旧 ReMe 文件。旧仓 ADR-0034 的 ReMe 工作区被本 ADR 替代；旧仓 ADR-0035 的「记忆始终开启」语义保留，但「全局层未接线时不装中间件」的条件在本仓 M1 不成立——本仓没有全局层，记忆始终装配。
6. **记忆不是消息正本**：记忆可以修订、可以重复；消息 append-only、不可改。记忆行不参与搜索命中、未读、唤醒、预算或任务状态。

## Consequences

- 记忆与业务正本同库、同备份、同迁移；不再需要 Agent 家目录、文件权限或「应用自管目录」的运维面。
- 关键词检索的召回质量低于 embedding；若未来要升级，需要新增 provider 与凭据面，届时另写 ADR，而不是在本 ADR 上悄悄加向量列。
- 记忆卡片是确定性摘要，不额外消耗模型调用；代价是它可能不如模型自写的记忆精炼。实现票可以用脚本化 provider 固定记忆写回行为，保证测试零成本。
- 旧 ReMe 文件留在磁盘上但不被读取；升级说明必须明确「不导入、不删除」。

## Old ADR Correspondence

- **替代**旧仓 ADR-0034（ReMe 工作区 / 记忆落点）：`reme/` 不再是记忆落点，改为 `agent_memory` 表。
- **保留**旧仓 ADR-0035（长期记忆始终开启）的「无开关」语义；「全局层未接线时才缺席」的条件在本仓 M1 不适用，因为本仓没有全局层。
- **部分替代**旧仓 ADR-0031 / ADR-0032 中关于 Agent 家目录 `reme/` 的落点部分；家目录的规则、技能与 MCP 声明在 M1 不实现，留给后续 Workspace 票，不在本 ADR 的替代范围内。
